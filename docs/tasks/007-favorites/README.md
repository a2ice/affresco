# 007 — Мобильная галерея и избранное AFFRESCO

Дата: 27.10.2026. Статус: **in_progress — код в main, независимый E2E пока не подтверждён**.

## Область изменений

Владелец согласовал обновление мобильной галереи перед реализацией избранного:

1. В секции «Коллекция» ссылка **«Как выбрать свой кадр»** находится над новой панелью.
2. Панель со статусом («Показано N из M»), иконкой обновления и мобильным переключателем **1 карточка / 3 карточки**.
3. На телефонах (ширина до 600px) панель использует `position:sticky;top:70px`, то есть доходит до нижней границы фиксированного хедера. Панель живёт внутри контейнера секции коллекции, поэтому перестаёт быть sticky после выхода из этой секции. Desktop использует обычную панель и сетку из 3 карточек; 601–900px без мобильного переключателя остаётся адаптивная сетка из 2 карточек.
4. Исходный мобильный режим **одна крупная карточка в ряду**, альтернативный — **3 миниатюры в ряду**. Выбор запоминается в `sessionStorage` этого браузера, подгрузка по 6 карточек и `IntersectionObserver` сохраняются.
5. Кнопка обновления каталога оформлена как квадратная кнопка-иконка, рядом с переключателем (одинаковая высота).
6. В шапке размещено контурное чёрное сердечко со счётчиком и кнопкой переключения `Все / Избранное`; на каждой карточке отдельная кнопка-сердечко. Не делать кнопку-сердечко вложенной в кнопку открытия редактора — карточка теперь `article`, внутри отдельные независимые `button.catalog-open` и `button.catalog-fav`.
7. Успешное добавление: возвращённый сервером артикул появляется в избранном, сердечко закрашено чёрным, счётчик увеличивается. Удаление — контурное сердце, счётчик уменьшается. Состояние загружается при открытии страницы. Ошибка сервера не приводит к ложному закрашиванию.
8. Нажатие на сердечко в шапке показывает только избранные карточки (пагинация тех же 6); повторное нажатие возвращает всю коллекцию. Пустое избранное показывает понятное сообщение с возвращением к общему каталогу.

## Хранилище и разделение аккаунтов

Временный серверный API: `public/api/favorites.php`.

- `GET /api/favorites.php` → `{items:[sku],count:number,scope:"guest"}`.
- `POST /api/favorites.php`, JSON `{action:"add"|"remove",sku:"6039"}` и `X-Affresco-Request: 1` → актуальный список/счётчик.
- Случайный ключ гостя находится **только в PHP-сессии**, управляемой HTTP-only SameSite=Lax cookie; на клиент он не передаётся.
- JSON каждого гостя записывается за пределами публичного `public/` (или во внутренний системный temp, если директория хостинга недоступна), файлы имеют права `0600`, при записи используется `flock()` для предотвращения гонок. Значения — исключительно валидированные артикулы, лимит 200.
- Гостевые данные **не переносить автоматически** в будущий аккаунт. После входа frontend должен получать только account favorites из отдельной приватной базы, после выхода — снова гостевые. До реализации 004 endpoint при наличии `afreska_user_id` намеренно возвращает `501 account_favorites_not_ready` вместо смешивания гостевого/аккаунтного списка.
- Изменение PHP-сессии в `public/api/session.php`: согласованный срок cookie 30 дней, httpOnly/SameSite, для согласованности с сохранением гостевого ключа. **Гарантия сохранности зависит от политики очистки PHP-сессий на хостинге**; постоянную account-базу и logout/login предстоит сделать в 004.
- Никакие user JSON или файлы с приватными ключами не входят в Git. Публичен только PHP-код API.
