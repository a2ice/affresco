# 012 — Непрерывный пользовательский путь: фреска → кроп → фото → примерка

Дата: 29.10.2026. Заказчик: владелец AFFRESCO. Основа: существующие `site.js`, `tryon.js`, `tryon-core.js` без дублирующего редактора.

## Цель и принятые UX-решения

- В пределах **текущей браузерной сессии** гостю и авторизованному пользователю доступны до **3 фото комнаты**. Хранение: IndexedDB для сжатых JPEG, sessionStorage для ID сессии/текущего выбора и геометрии. После закрытия модала/обновления страницы в рамках сессии не требуется повторная загрузка фото. На экране выбора фото три миниатюры/слота с возможностью удаления и замены.
- Собственные изображения фресок добавляются на этапе кропа или при замене в примерке. Пользователь **обязательно** вводит физическую ширину и высоту (30–1000 см), файл проверяется на формат/размер/пиксели и сжимается локально. До 12 личных вариантов в сессии; они показаны в локальном каталоге и подборе, без публикации на сервер и без серверных избранных. Данные отделены по сессиям.
- Нижняя мини-навигация fixed **20px от нижнего края по центру**, только **назад** на данном этапе, компактно сворачивается до иконки и восстанавливается без удаления состояния. Место для перехода вперёд предусмотрено позже.
- Подтверждение стены — через кнопку переключателя `Подтвердить стену`, после чего `Стена`; отдельная кнопка и длинный текст удалены. Стена после изменения геометрии вновь требует подтверждения.
- По клику внутри фрески активна фреска, внутри стены вне фрески — стена, вне обоих объектов выделение снимается. Сохраняется существующая манипуляция углами, увеличение и перемещение вида.
- При активной фреске кнопки `Изменить фреску` (зелёное выделение, вертикальный список с поиском/SKU и внешним крестиком) и `Кроп-редактор` (красное выделение, переход в существующий редактор). Перед повторным применением каталог/кроп не удаляют выбранную комнату.
- Кроп-редактор умеет вернуть полное каталожное изображение; `Отменить` в футере примерки через фирменное подтверждение `Состояние примерки будет возвращено к исходному` возвращает начальное состояние текущего входа в примерку. При смене фрески первоначальная композиция не теряется.
- Неподходящие физические размеры новой фрески: 500мс красное выделение миниатюры, фирменный toast, переход в кроп. Кроп явно подсвечен, а его пределы указываются текущей стеной. Кнопки сохранения/выгрузки/AI заблокированы пока размеры не подходят; самопроизвольное уменьшение без пользователя запрещено. **Введённые самим пользователем меньшие размеры принимаются как заявленные физические размеры**, а не оцениваются по пикселям.
- Информационный блок над сценой: `Расположение фрески*: Слева N см; Снизу N см`, с title `* Относительно выделенной области стены`; под ним единым шрифтом — размер и масштаб фрески.
- Пресет стены — собственный listbox `ul/li` с UI и клавиатурным управлением; ручные размеры переводят в `Свой размер`.
- Необязательная кисть маски перемещена в кнопку фломастера снизу справа на сцене, панель раскрывается вверх, размер 3–80px, undo/clear, по умолчанию скрыта.

## Файлы

- `public/assets/js/tryon-library.js` — новый scoped IndexedDB модуль (без передачи фото на сервер только для кэша).
- `public/assets/js/tryon.js` — восстановление комнат и layout, управление стеной/фреской, сценой, каталогом, ограничениями, маской.
- `public/assets/js/site.js` — кроп/собственные изображения, каталог и мост между модальными редакторами, возврат к шагам.
- `public/index.html`, `public/assets/css/tryon.css` — компоненты и адаптивные стили.
- `tests/tryon-session.cjs`, `tests/tryon-upload.cjs`, `.github/workflows/deploy.yml` — регрессии и CI.

## Приёмка / проверка

1. Гость открывает кроп → примерка → загружает фото, закрывает/возвращается назад, снова примеряет другую фреску — фото доступно. До 3 фото, четвёртое не добавляется до удаления.
2. Авторизация/выход из аккаунта не удаляют кеш фотографий в пределах сессии.
3. Собственная фреска без указанных размеров отклоняется; с размерами попадает в локальный каталог и подбор. После перезагрузки в той же сессии доступна. Избранное не отправляется в общий серверный каталог.
4. Стена подтверждается только верхней кнопкой; после изменения геометрии повторное подтверждение. Клики на сцене изменяют активный слой, пустая зона снимает оба выделения.
5. Смена фрески через панель, возврат в кроп и `Восстановить`, отмена через фирменный диалог не сбрасывают загруженные фото без явного действия.
6. Недопустимые физические размеры: красная вспышка 500мс, toast, кроп с ограничениями; пока размер не скорректирован, нельзя применить/скачать/отправить/запустить AI. После корректировки параметры принимаются.
7. Nav на desktop/mobile фиксирован по центру с 20px снизу, сворачивание/разворачивание; доступность клавиатурой.
8. AI-запросы, квоты, авторизация, серверное хранение, ZIP/email и физическая перспектива не должны регрессировать.

**Ограничения:** без удалённой графической E2E-проверки (Dmitanium был offline при работе) корректность всех визуальных взаимодействий desktop/mobile остаётся предметом ручной приёмки владельца. CI проверяет библиотеку, существующие регрессии и ограничения, но не подменяет реальные browser click/drags.

## 29.10.2026 — Правки приёмки по скриншотам (PR #30)

Владелец проверил первый релиз #29 и потребовал корректировку, не расширяя остальной функционал.

- **Breadcrumbs:** вместо единственной кнопки назад — компактная фиксированная бежeвая горизонтальная полоса по фактической ширине бейджей, центр и 20px от низа, padding 5px 10px, radius 8px. Кликабельные чёрные бейджи «Выбор фрески», «Кадрирование», «Фото комнаты», «Примерка» появляются по мере прохождения; возврат к прежнему этапу убирает последующие бейджи. Сворачивание сохранено.
- **Собственная фреска:** ссылка «Загрузить своё изображение» под изображением кроп-редактора открывает системный file picker. После выбора открывается фирменный popup с превью, необязательным названием («Моя фреска №N» по умолчанию) и обязательными см. Нажатие «Применить» проверяет размеры, сохраняет файл на сервере, выставляет новый рисунок в кроп-редакторе и бейдж «Изображение добавлено в каталог». Личные изображения первыми появляются в каталоге и при замене фрески.
- **Серверное хранение вместо IndexedDB:** `public/api/media.php` хранит JPEG в закрытом каталоге `.affresco-user-media` рядом с защищённым `.affresco-account-state` (с fallback того же безопасного хранилища). Для аккаунтов **метаданные и привязка файлов хранятся в закрытом `accounts.json`** (массив `media_assets`), для гостей — в PHP-сессии. Ни бинарные файлы, ни секреты не добавляются в git, прямого публичного URL к каталогу нет; изображение обслуживается через cookie-authenticated API только владельцу. Обязательная проверка Origin, запрет cross-site POST, MIME/пикселей/размеров, max 12MB, серверная блокировка изменения accounts.json при записи.
- **Лимиты независимо для фото комнаты и своих фресок:** гость — по одному (повторная загрузка заменяет прежнее), вошедший пользователь — по три (при достижении лимита надо удалить имеющееся). На экране загрузки комнаты пустые плитки больше не рисуются; показываются только реально сохранённые миниатюры. Фото комнаты до загрузки сжимается браузером в JPEG и безопасно отправляется на сервер.
- **Упрощение примерки:** убраны все кнопки «Подтвердить стену», «Выбрать другое фото» и «Вернуться к кадру»; стена доступна сразу после загрузки фото, переключатели слоёв называются «Стена» и «Фреска». Шаги назад и смена комнаты теперь только через breadcrumb.
- [PR #30](https://github.com/a2ice/affresco/pull/30). CI тесты `tests/tryon-session.cjs` проверяют клиентский серверный адаптер, квоты guest/account 1/3 и удаление; `tests/tryon-upload.cjs` проверяет открытие сцены без дополнительного подтверждения и прежний функционал. PHP-файлы проверяются `php -l`. Независимый браузерный E2E не выполнен (Dmitanium offline).
- **Обязательно после deploy:** проверить публичный POST с гостевой сессией, сохранение при авторизации, недоступность чужих фото, и реальный upload MIME в продовой конфигурации CISHOST. Не объявлять пользовательский PASS без подтверждения владельца.
