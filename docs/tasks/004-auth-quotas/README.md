## Реализация демо-авторизации и личного кабинета — 28.10.2026

**Статус: реализация в `main`, ожидает независимую E2E-проверку реального входа и записи статистики.** Не помечать этап PASS без тестового входа в браузере.

Источник аккаунтов на FTP: `/data/accounts.json` (массив). Также поддерживается приватный `../data/accounts.json` вне корня сайта; путь выбирает `public/api/_account.php`. Файл с паролями **не хранится в Git**, в `public/data/.htaccess` закрыт HTTP-доступ; внешний GET `https://affresco.a2ice.ru/data/accounts.json` вернул **403**. Старый JSON с MD5 удалён из `main`; историю GitHub это не очищает. Владелец сменил пароли через `password_hash()` на FTP.

Формат одной записи: `id`, `login`, `pass` (PHP `password_hash`), `generations_limit`, `generations_used`, `generations_failed`, `last_login`, `login_count`, `last_update`, `updates_count`, `updated_items_sku`. Старые поля сохраняются. `_usage.php` вносит `last_login`/`login_count` только при успешном входе и `last_update`/`updates_count`/`updated_items_sku` после серверного сохранения кадра. Лимиты/использование генераций пока не меняются: генерация (задача 005) не подключена. При недоступности записи на FTP аналитика обновляться не сможет — проверить права PHP.

API: `GET /api/auth.php` возвращает свой статус сессии; `POST /api/auth.php` с `X-Affresco-Request: 1`, JSON `{action:"login",login,password}` либо `{action:"logout"}`. Пароль проверяется `password_verify()`, не возвращается. Пять неудачных входов за 15 минут блокируют новые попытки в текущей сессии. При входе/выходе регенерируется PHP session ID; браузер после успеха перезагружается и получает новую область данных.

`GET/POST /api/account-state.php` работает только с авторизованной сессией и хранит избранные SKU и сохранённые настройки кропа по ID аккаунта в отдельном приватном JSON, вне публичного дерева либо в приватной директории PHP-temp при ограничениях хостинга. **Гостевое избранное и гостевые локальные черновики автоматически в аккаунт НЕ переносим.** Гостевая область остаётся доступной после выхода.

Интерфейс: `public/assets/js/account.js` (loaded before `site.js`), `public/assets/css/account.css` и `public/index.html`. Пароль отправляется только через `fetch`/POST JSON; сама форма имеет `method=post`, поэтому при сбое JavaScript пароль не окажется в URL. Авторизованный логин появляется в шапке, по нажатию открывается кабинет со счётчиками генераций, избранного, сохранённых кадров, статистикой входов/редактирования, списками SKU и выходом. На мобильном экране логин виден вместо CTA в шапке, CTA доступна в остальном содержимом; гостям вход доступен также в меню.

**Проверено:** публичный GET `/api/auth.php` без сессии → `{"authenticated":false}`; `/api/account-state.php` без сессии → HTTP 401; `/data/accounts.json` → HTTP 403; обе JS-сборки парсятся без ошибок; изолированный JS тест гостевого/аккаунтного избранного и входа/выхода PASS. Эти проверки не заменяют реальный POST с тестовым аккаунтом и браузерную проверку.

**E2E-план:** на `https://affresco.a2ice.ru/` в браузере 390px и desktop: (1) открыть вход, проверить одинаковые поля логина/пароля; (2) ввести реальный тестовый логин, убедиться в отсутствии пароля в URL; (3) в шапке — логин, по клику кабинет; (4) добавить два SKU в избранное и кадрировать одну фреску, обновить страницу — значения остались; (5) выйти — видны только гостевые данные, при повторном входе — данные аккаунта; (6) подтвердить на FTP `last_login`, `login_count`, `last_update`, `updates_count`, `updated_items_sku`; (7) `generations_used` не растёт без успешной генерации. Не использовать реальные клиентские пароли в отчётах.
