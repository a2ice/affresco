# AI-примерка интерьера — GitHub Actions и OpenAI

Дата: 28.10.2026. Реализация в ветке `feat/ai-room-tryon-github-20261028`. Источник архитектуры: [MSKBA workflow](https://github.com/a2ice/mskba/blob/main/.github/workflows/openai-player-generate.yml) + подписанный manifest/callback. Оригинальный проект MSKBA не изменяется.

## Продуктовые условия

- В футере ручной примерки — AI-кнопка; гость при нажатии попадает в существующий попап авторизации. Успешный вход возвращает его в примерку и **автоматически запускает тот же запрос**. Закрытие авторизации отменяет ожидающий запуск.
- Только авторизованный аккаунт с остатком `generations_limit - generations_used` может вызвать серверный POST. Счётчик резервируется атомарно; повторные запросы при уже работающем задании в этой примерке запрещены. При ошибке dispatch/callback или таймауте резерв возвращается.
- После принятия GitHub dispatch кнопка disabled, показан toast «Генерация началась». При любом терминальном исходе toast исчезает; при ошибке выводится русское сообщение. Пуллинг статуса 3,5 секунды без блокировки остального редактора.
- Входные изображения: (1) исходная комната (без фрески); (2) исходный кроп фрески; (3) текущая ручная JPEG-примерка как ориентир геометрии. Дополнительные метаданные: размеры стены и фрески в см, нормализованные углы квадов и свет.
- **Единый неизменяемый промпт** в `public/api/_ai_tryon.php:af_ai_prompt`. Исходная комната — эталон композиции и мебели; фото ручной примерки — только эталон размещения. Предметы переднего плана (диван, стол, растения и др.) обязаны закрывать фреску, если расположены ближе к камере. Это вероятностный AI-результат, не гарантированный алгоритм маскирования; не представлять как пиксельно точное измерение.
- Каждый результат хранится на сервере в приватной директории соответствующего пользователя. Новый вариант появляется **ниже** предыдущих и вызывает scroll внутри попапа.
- До шести вариантов на одну примерку; архив скачивается по авторизованному GET, email с ZIP отправляется через существующий SMTP попап и требует авторизации. История браузерных ручных JPEG остаётся отдельно.
- Нет ключей в браузере, публичных JSON или GitHub файлах.

## Архитектура

`public/api/ai-tryon.php`: POST принимает `multipart/form-data` (3 JPEG и короткий metadata JSON), проверяет сессию/квоту, сохраняет JPEG в приватное хранилище, делает `workflow_dispatch`. GET статус по `context`, изображение по `image` только владельцу. Приватный manifest и URL трёх исходных фотографий доступны GitHub runner только по HMAC-подписанным ссылкам с TTL. `POST ?callback=id` — signed HMAC SHA-256 по timestamp + id + status + SHA-256 content, не зависит от пользовательской cookie.

`.github/workflows/openai-room-tryon.yml`: GitHub Actions получает **только ID**, генерирует HMAC-подпись на URL manifest уже внутри runner, загружает 3 JPEG, вызывает OpenAI `/v1/images/edits` с `gpt-image-2`, возвращает signed processing/completed/failed callback. Ключ OpenAI и callback secret — GitHub Actions Secrets. Ссылка на приватный manifest **не передаётся в публичных workflow inputs**. Версия задания: workflow из `main`.

`public/api/ai-tryon-export.php`: ZIP по `context` только владельцу, до 6 PNG; POST — тот же ZIP как вложение через SMTP (при наличии `ZipArchive`, PHPMailer и настроенной почты). `public/assets/js/tryon.js`, `site.js`, `index.html`, `tryon.css` — интерфейс, авторизация, toast, галерея, сохранение ZIP.

## Приватная конфигурация перед включением

Нужны **раздельные** настройки:

1. В GitHub репозитории `a2ice/affresco`: Secrets `OPENAI_API_KEY` и `AFFRESCO_AI_CALLBACK_SECRET`. Не копировать значения в git или в ответ чата. GitHub Actions Variable `AFFRESCO_AI_PUBLIC_URL` — `https://affresco.a2ice.ru` (или `https://afreska.2ice.ru` при проверенном основном домене). OAuth/PAT токен dispatch хранится **только на сервере**.
2. На CISHOST по решению владельца конфигурация размещена в `public/data/affresco-ai.json` (веб-корень `/data/`). **Это допустимо только если веб-сервер подтверждённо запрещает HTTP-доступ** к `affresco-ai.json`, `accounts.json`, `mail.json` и резервным JSON. Отдельно [PR #15](https://github.com/a2ice/affresco/pull/15) добавил Apache `.htaccess` и post-deploy HTTP HEAD-проверку статусов 403/404; публичный `catalog.json` должен отвечать 200. Структура файла:
```json
{
  "github_repo": "a2ice/affresco",
  "github_token": "SET_ON_SERVER_ONLY",
  "callback_secret": "MUST_EQUAL_GITHUB_SECRET",
  "public_url": "https://affresco.a2ice.ru"
}
```
3. На сервере должны быть PHP `curl`, `ZipArchive` (для ZIP), writable приватная директория `.affresco-ai` для результатов **вне document root**, корректные HTTPS сертификаты, запрет доступа к JSON в `/data/` и корректная доставка SMTP. Разрешение на конфигурацию в `public/data` не распространяется на исходные пользовательские фотографии и AI-результаты.
4. GitHub token: minimum workflow dispatch/actions write permissions для одного репозитория. Ключ OpenAI с ограниченным бюджетом проекта. Проверить счётчики `generations_limit` в аккаунтах; по умолчанию без квоты запуск запрещён.
5. Закрытые страницы могут быть доступны по двум историческим доменам; HMAC URL в manifest всегда формируется по `public_url` сервера. Проверить точный внешний HTTPS URL до боевого запуска.

**Без обоих Secret и защищённой серверной конфигурации кнопка вернёт понятное `ai_not_configured`, и ни один платный OpenAI запрос не должен запускаться.** Даже если CI пройдёт, это не означает, что платная генерация и реальная окклюзия проверены.

## Приёмка

1. Гость → AI → попап авторизации → успешный вход → запрос автоматически начался без второй кнопки; закрытие окна входа не запускает.
2. Повторный клик во время обработки не создаёт второй платный вызов. Toast исчезает при успехе и ошибке. Таймаут и неуспешный callback корректно возвращают квоту.
3. Исходное фото с диваном, пересекающим место фрески: в AI-результате диван должен остаться **впереди**, фреска — **за ним**, обстановка не должна заметно меняться. При плохом AI результате — регенерация.
4. Несколько результатов добавляются ниже и не заменяют друг друга; есть автопрокрутка к последнему и сохранение на сервере.
5. ZIP скачивается без смешения пользователей, письмо отправляет ZIP и не публикует пользовательские фотографии. Без PHP ZipArchive — понятная ошибка.
6. CI `node --check`, PHP lint, существующие тесты и `tests/ai-tryon.php`; отдельный реальный интеграционный прогон с настоящими Secret (без выдачи логов с ключами).
7. E2E-инструменты временно недоступны, ручную визуальную проверку проведёт владелец; не записывать её как PASS до фактического подтверждения.

## Статус

Код на ветке / PR, владелец сообщил, что настроил GitHub Secrets и загрузил конфигурацию в `public/data`, но их фактическую пригодность и запрет скачивания по HTTP нужно проверить. Платные вызовы не производились. Не выдавать CI за функциональный E2E. Не мержить до устранения конфигурационного блокера и проверки экономики.
