# 008 — Внешнее рабочее поле и независимая перспектива стены

Дата решения: 28.10.2026. Решение владельца по примеру фотографии, где часть прямоугольной стены обрезана рамкой снимка: **сначала калибруем полный четырёхугольник стены в сантиметрах, затем размещаем фреску в этой системе координат**.

## Проблемы и требования

1. Реальные углы стены могут находиться за краями фотографии — запрещено привязывать геометрию к рамке файла. При этом отсутствие видимых физических углов ограничивает точность восстановления перспективы.
2. Крайние маркеры должны сохранять доступную область захвата на мыши и тачскрине (целевой размер >= 44 CSS px).
3. Панорамирование и масштабирование — только свойства **камеры рабочего поля**, без изменения wallQuad, placement_cm, сохранённых размеров и JPEG.
4. Проецируемая фреска следует гомографии wallQuad; Canvas и JPEG обрезают отображение по границам исходного фото. Разметка редактора в экспорт не входит.
5. Не менять серверные эндпоинты, лимиты, автосохранение, систему квот, свет и пользовательские фото.

## Реализация в ветке feat/tryon-infinite-wall-workspace-20261028

- `public/assets/js/tryon-core.js`: геометрия `freeCorner`, `freeTranslate` отделена от прежних ограниченных функций; `viewTransform`, `zoomViewAt`, `fitQuadView` — чистая математика viewport. Координатные пределы ±20 размеров фото — защита от нечисловых/патологических значений, а не граница фотографии.
- `public/index.html`: панель Zoom −/+, «Вписать фото», «Показать стену», контекстная подсказка.
- `public/assets/css/tryon.css`: отделённая область stage с overflow:hidden; canvas плавает внутри, SVG-маркеры накладываются на всю площадь stage, а не обрезаются фотографией.
- `public/assets/js/tryon.js`: pointer capture на stage, захват углов радиусом 24 CSS px (диаметр 48), pan на свободном поле, touch pinch, Ctrl+wheel, восстановление доступности хэндлера после выхода к краю viewport. Zoom/pan не меняют revision; перемещение геометрии меняет.
- `tests/tryon-core.cjs`, `tests/tryon-upload.cjs`: расширенные проверки геометрии, инвариантности масштаба, положения за границами фото и сохранения координат.

## Ручная проверка до публикации

- Desktop: загрузить фото; вытянуть каждый угол стены за левую/верхнюю/правую/нижнюю границы фото; угол остаётся видимым и управляемым, когда находится внутри рабочего поля.
- Desktop: масштаб +/−, fit photo, fit wall, Ctrl+wheel с якорем на курсоре, pan по пустому полю.
- Mobile: захват угла пальцем рядом с рамкой фото, pan одним пальцем на пустом поле, pinch двумя пальцами; отсутствие горизонтального скролла страницы при жесте на сцене.
- Стена → Фреска: после корректировки перспективы фреска наследует её, сохраняет точные сантиметровые пропорции, не выходит за границы стены.
- Сохранить/скачать/отправить: photo output не включает рабочее поле или хэндлеры; zoom/pan никак не меняет пиксели JPEG; после реального изменения перспективы новый результат имеет новую ревизию.
- Переключение слоёв, свет, сброс перспективы, клавиатурные стрелки и фокус, загрузка новой комнаты, desktop/mobile resize.

## Статус и границы приёмки

CI по PR #11 пройден (синтаксис JS/PHP и автоматические тесты). **28.10.2026 владелец явно разрешил merge в main и публикацию по готовности без независимого E2E**, поскольку E2E-инструменты временно недоступны, и обязался сам проверить результат. Это временное исключение из стандартного процесса, а не E2E PASS. Функциональная приёмка остаётся открытой до фактической ручной проверки владельца; замечания исправляются отдельными PR. Фактический статус deploy проверяется по GitHub Actions, а не предполагается по merge.

Важно: для невидимой геометрии пользователь вручную оценивает положение внешних углов по линиям интерьера. Редактор не обещает автоматического восстановления реальных физических углов по одному фото.
