## Каталог: подгрузка порциями и подготовка фотографий

- Desktop: **3 карточки в ряду**. До 900px — 2 в ряду, до 480px — 1.
- При первом получении списка JSON рендерятся **только 6 карточек**. Далее по **6 карточек за раз** при приближении к концу видимого списка, через `IntersectionObserver` (rootMargin 0px — только при приближении к видимому краю списка). Имеется доступная кнопка «Показать ещё» на случай, если автоподгрузка недоступна.
- Показывать круговой лоудер на время загрузки изображений очередной порции; **не добавлять новые карточки в сетку до готовности фотографий**, чтобы индикатор не смещался за пределы видимой области. Для дополнительных порций визуальная смена состояния занимает минимум 300 мс, даже при кеше; это только задержка показа, сами загрузки не замедляются. Ошибка отдельного файла не блокирует следующую порцию. После исчерпания списка индикатор и кнопка скрываются.
- Превью всех пропорций — единый контейнер; `object-fit: cover; object-position: center`. Кадрирование в **карточке** визуальное и не должно менять оригинальный файл/координаты кроп-редактора. В редакторе использовать полноразмерный файл, преимущественно из `Images/prepared/` при наличии, а не обрезанное превью карточки. Оригинал с линейками остаётся на FTP для считывания размеров.
- Раздельные папки: `/Images/catalog/` хранит оригиналы с размерами, `/Images/prepared/` — очищенные версии. API подбирает подготовленное фото по совпадающему артикулу, иначе оставляет оригинал. Справочник физических размеров и ориентации — [docs/CATALOG_METADATA.md](../../CATALOG_METADATA.md) и [public/data/catalog.json](../../../public/data/catalog.json). Значения вводим по диктовке, пока они отсутствуют.
- Владелец готовит в **отдельной папке `Images/prepared`** версии без технических подписей сантиметров, линеек и управляющих маркеров; исходные изображения с линейками не заменяет. Не скрывать их через CSS — они являются частью исходного файла. Сохранять исходный артикул в имени.
- Изображения в GitHub не дублировать; каталог загружается из выделенной FTP-папки, защищённой от удаления деплоем.

**Техническая проверка:** записаны в `main` HTML/CSS/JS для пагинации, скрипт синтаксически разобран. **Проверка в браузере, включая реальную прокрутку и фотографии, пока не подтверждена.**

## Выбор фрески для редактора (27.10.2026)

- Превью основной коллекции остаются по 3 в ряд на десктопе, но уменьшены по высоте приблизительно на **23%** изменением соотношения сторон с `0.89` на `1.15`; `object-fit:cover`, оригиналы не меняются.
- Два самостоятельных UX-маршрута: **карточка → сразу crop** с выбранным артикулом; **кнопка «Открыть редактор» в секции «Создайте свой кадр» → отдельное модальное окно выбора → crop**. Не выбирать первый артикул без действия пользователя.
- Модалка поиска: поле с подсказками по артикулу / названию, поиск по подстроке без учёта регистра, Enter выбирает первый результат, кликабельные подсказки. Пустая выдача показывает понятный текст, не открывает редактор.
- В окне выбора: визуальные карточки с фотографией и артикулом, **по шесть на порцию**, подгрузка следующих при прокрутке внутри окна через `IntersectionObserver`; доступная запасная кнопка «Показать ещё». Переходы модалок сохраняют возврат фокуса к исходной кнопке.
- В crop-редакторе над фотографией есть кнопка **«← Выбрать другую фреску»**. Она открывает существующий `pickerModal` без закрытия пользовательского сценария: по поиску/артикулу выбирается другая фреска и вновь открывается crop. Если редактор открыт из pop-up выбора — запрос поиска сохраняется; если из каталога — список выбора открывается целиком. Текущая рамка сохраняется в локальном черновике выбранного артикула до переключения, чужой артикул не перезаписывается.
- Проверить вручную: `главная → открыть редактор → выбрать 6247 → выбрать другую фреску → выбрать иной артикул → кадрировать`, а также `каталог → карточка → выбрать другую фреску`; проверить возврат фокуса и маленький экран. Коммит в `main`; визуальная браузерная/E2E-проверка пока не подтверждена (27.10.2026: Windows `Dmitanium` офлайн).
- Источник данных у обоих путей единый: `/api/catalog.php`; выбор работает также для артикулов, представленных в JSON числами. Кадрировать только явно выбранную фреску, использовать уже существующий механизм localStorage-черновика по артикулу.
- Проверка: исходный HTML, CSS и синтаксис JS сохранены в `main`. **Ручная браузерная проверка popup / mobile и независимый E2E ещё нужны; Remote Desktop Commander `Dmitanium` офлайн.**

## Crop-редактор с изменяемой рамкой (27.10.2026)

Статус: **in_progress / ожидает браузерную и независимую E2E-проверку**. Реализация в `main`; последняя ревизия версионируемых ресурсов `crop-20261027-1`.

- Перекомпонована бежевая панель: ссылка «← Выбрать другую фреску» находится отдельно над рабочей областью, без искусственного 80px промежутка и подчёркивания стрелки; фото смещено выше.
- Область crop теперь отдельно от полного изображения и имеет **8 маркеров**: 4 угла + 4 стороны. Маркеры можно тянуть мышью или пальцем, а клавишами-стрелками на выбранном маркере выполнять точные изменения. Изображение перетаскивается **внутри рамки**, колесо/ползунок меняют масштаб.
- Галочка **«Сохранять пропорции кадра»** по умолчанию включена. В этом режиме рамка меняется с фиксированным соотношением сторон, в выключенном — свободно, с синхронизацией сантиметровых полей под изменённый формат. Пресеты 4:3/16:9/1:1/3:4 включают фиксированные пропорции; изменения ширины/высоты обновляют рамку.
- Кнопка **«Восстановить исходный кадр ↺»** возвращает всю исходную композицию (100%, нулевое смещение, рамка по границам исходного изображения, актуализированные сантиметровые поля). `Сохранить кадр` сохраняет нормализованную область, соотношение сторон и черновик по артикулу в `localStorage`; старые черновики без поля `selection` совместимы.
- Для актуализации браузера проставлен параметр версии на `editorial.css` и `site.js`.

**Проверки в коде:** HTML содержит 8 маркеров и чекбокс; JavaScript успешно компилируется, алгоритм изменения рамки проверен для восьми маркеров как с закреплёнными, так и со свободными пропорциями. **Не проверено в опубликованном браузере:** жесты перетягивания, пересчёт выделения, поведение на узком экране, отсутствие ошибок консоли/сети. Удалённый компьютер Dmitanium офлайн; попытки получить `https://afreska.2ice.ru/` через внешние инструменты вернули недоступность / invalid_url, а отсутствие GitHub commit-status не подтверждает FTP-деплой. Независимый чат `e2e_` не создан: нет доступного GUI ChatGPT в проекте A2ice; результат независимого E2E не заявляется.

### Handoff для независимого E2E

Адрес: `https://afreska.2ice.ru/`; код: [AFFRESCO main](https://github.com/a2ice/affresco/tree/main); ревизия последнего обновления UI `5c6c74af023cf7e3e27b9f424095aa2c9215f0d9`. Убедиться, что именно эта версия дошла до FTP и не закрыта старым кешем. Проверять desktop 1440px и мобильный 390px, без логина и отправки данных:
1. Коллекция → открыть карточку → редактор. Убедиться, что ссылка смены фрески аккуратно размещена, «Выбрать другую фреску» ведёт в попап и позволяет выбрать другой артикул.
2. В редакторе передвигать изображение внутри рамки; потянуть каждый из 4 краёв и 4 углов; с включённым переключателем пропорции остаются постоянными, выделение в пределах изображения.
3. Отключить переключатель, изменить рамку горизонтальной и вертикальной ручкой по отдельности — форма изменяется свободно, поля сантиметров актуализируются, изображения без растяжения.
4. Проверить пресеты 4:3, 16:9, 1:1, 3:4; изменение числовых размеров; масштабирование ползунком и колесом мыши.
5. Сохранить кадр → закрыть/открыть тот же артикул (черновик восстановился), сменить артикул (кадры не смешаны); восстановить исходный кадр (исходная композиция, масштаб 100% и полный вид).
6. Проверить отсутствие пересечений элементов на 390px, работу пальцем/мышью, клавиатурой, закрытие модалки и отсутствие блокирующих JS-ошибок.

Формат отчёта: **PASS** либо **FAIL** с пунктом, шагами, ожидаемым и фактическим результатом. При FAIL — исправление и повторная адресная проверка до PASS.
