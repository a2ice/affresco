## Каталог: подгрузка порциями и подготовка фотографий

- Desktop: **3 карточки в ряду**. До 900px — 2 в ряду, до 480px — 1.
- При первом получении списка JSON рендерятся **только 6 карточек**. Далее по **6 карточек за раз** при приближении к концу видимого списка, через `IntersectionObserver` (rootMargin 0px — только при приближении к видимому краю списка). Имеется доступная кнопка «Показать ещё» на случай, если автоподгрузка недоступна.
- Показывать круговой лоудер на время загрузки изображений очередной порции; **не добавлять новые карточки в сетку до готовности фотографий**, чтобы индикатор не смещался за пределы видимой области. Для дополнительных порций визуальная смена состояния занимает минимум 300 мс, даже при кеше; это только задержка показа, сами загрузки не замедляются. Ошибка отдельного файла не блокирует следующую порцию. После исчерпания списка индикатор и кнопка скрываются.
- Превью всех пропорций — единый контейнер; `object-fit: cover; object-position: center`. Кадрирование в **карточке** визуальное и не должно менять оригинальный файл/координаты кроп-редактора. В редакторе использовать полноразмерный файл, преимущественно из `Images/prepared/` при наличии, а не обрезанное превью карточки. Оригинал с линейками остаётся на FTP для считывания размеров.
- Раздельные папки: `/Images/catalog/` хранит оригиналы с размерами, `/Images/prepared/` — очищенные версии. API подбирает подготовленное фото по совпадающему артикулу, иначе оставляет оригинал. Справочник физических размеров и ориентации — [docs/CATALOG_METADATA.md](../../CATALOG_METADATA.md) и [public/data/catalog.json](../../../public/data/catalog.json). Значения вводим по диктовке, пока они отсутствуют.
- Владелец готовит в **отдельной папке `Images/prepared`** версии без технических подписей сантиметров, линеек и управляющих маркеров; исходные изображения с линейками не заменяет. Не скрывать их через CSS — они являются частью исходного файла. Сохранять исходный артикул в имени.
- Изображения в GitHub не дублировать; каталог загружается из выделенной FTP-папки, защищённой от удаления деплоем.

**Техническая проверка:** записаны в `main` HTML/CSS/JS для пагинации, скрипт синтаксически разобран. **Проверка в браузере, включая реальную прокрутку и фотографии, пока не подтверждена.**

### Исправление расчёта размеров при drag (27.10.2026)

- **Обнаруженный дефект:** старая `syncDimensionsToSelection()` сохраняла ширину в сантиметрах и пересчитывала высоту как `width / aspect`. При сужении рамки справа или слева после снятия галочки высота необоснованно **увеличивалась** (воспроизведено по скриншотам владельца для артикула 6039).
- **Исправление:** `syncDimensionsAfterResize(before, after, startWidthCm, startHeightCm)` теперь пересчитывает `width_cm = initial_width_cm * new_crop_pixel_width / initial_crop_pixel_width` и аналогично высоту — **независимо** для каждой оси. Берутся значения на момент начала drag (не округлённые числа предыдущих событий).
- С выключенным `Сохранять пропорции кадра`: боковые ручки меняют только ширину, верхняя/нижняя — только высоту, угловые — обе величины. С включённым флажком изменяются оба размера пропорционально геометрическому выделению; включение флажка само по себе не меняет сантиметры.
- То же вычисление применяется к клавиатурному изменению рамки; существующие draft в `localStorage` остаются в исходном формате. В `public/index.html` JS подключён с новой версией `crop-20261027-4`.
- **Проверка:** синтаксис актуального JS, программное исполнение фактической функции геометрии вместе с новым расчётом для 8 ручек × 2 режима блокировки — 16/16 сценариев с корректной динамикой полей. **Не подтверждено:** браузерная и независимая E2E-проверка деплоя. В E2E повторить сценарий `150 × 76` → снять галочку → сужать за правую ручку: уменьшаться должна **ширина**, а `76` должно остаться постоянным; затем поменять высоту верхним маркером, проверить угол и включённую галочку.

### Новый UX кадрирования: затемнение и перемещение выделения

- По запросу владельца рамка стала **перемещаемой по неподвижной фотографии**, а не наоборот. Внутри рамки pointer-drag меняет координаты `selection.x/y` с ограничением по границам изображения; относительные размеры `selection.w/h`, ширина/высота в сантиметрах и трансформация исходной фотографии при этом **не меняются**.
- Фотография `crop-image` остаётся в отдельно обрезаемом `.crop-image-clip`. Четыре полупрозрачные накладки внутри `crop-dim-layer` затемняют верхнюю, правую, нижнюю и левую зоны *вне* выделения. Слой затемнения не получает события указателя и обрезается только по границам фотографии; ручки рамки находятся над ним, не обрезаются. Накладки синхронизируются с координатами crop при обновлении, перетаскивании, изменении размера и сбросе.
- Существующие resize-маркеры, сохранение в `localStorage` по артикулу, нормализованные координаты, ratio-lock и отдельное масштабирование продолжают работать. Версия подключенных статических ресурсов обновлена на `crop-20261027-5`.
- **Техническая проверка:** синтаксис JS; восемь сценариев перемещения в центре, по каждой оси, к границе и с полной 100%-рамкой (8/8); сверены четыре CSS-панели, соответствующие элементы в HTML и обновление координат в JS. **Браузерная и независимая E2E-приёмка пока не подтверждены.**
- **Обязательная проверка после деплоя:** взять фреску с уже уменьшенной рамкой (например, артикул 6404), убедиться, что за пределами рамки фреска темнее; перетащить рамку за середину и убедиться, что фотография стоит неподвижно, размеры не меняются, рамка не выходит за край; потянуть край и угол, проверить обновление затемнения; сохранить, закрыть и снова открыть артикул; проверить 100%-сброс, zoom и мобильное касание.
