# 002 — Адаптивный лендинг

Статус: **in_progress**. 27.10.2026 разработан первый MVP лендинга и редактора; выполнен редакционный дизайн-проход v0.2 в `main`. Визуальная и независимая E2E-приёмка обновлённой версии ещё не проведены.

По предоставленному заказчиком референсу создать главную страницу для премиальных настенных фресок, демо-каталог из ограниченного набора материалов, адаптивность, доступность и высокую производительность.

## Реализация v0.2 (проверка ещё требуется)

- Главная: `public/index.html`, базовые стили `public/assets/css/site.css`, токены `public/assets/css/design-tokens.css`, визуальный слой `public/assets/css/editorial.css`.
- Каталог: `public/api/catalog.php` формирует JSON из загруженных владельцем файлов в `Images/catalog/` или `Images/каталог/`; артикул выводится из имени файла без расширения.

- Дизайн v0.2: убраны CSS-имитация интерьера и верхняя демо-плашка, усилены типографика, фотографическая композиция, карточки, редактор и мобильные стили. Содержательный статус демонстрации остаётся на странице.

## Каталог: подгрузка порциями и подготовка фотографий

- Desktop: **3 карточки в ряду**. До 900px — 2 в ряду, до 480px — 1.
- При первом получении списка JSON рендерятся **только 6 карточек**. Далее по **6 карточек за раз** при приближении к концу видимого списка, через `IntersectionObserver` (rootMargin 250px). Имеется доступная кнопка «Показать ещё» на случай, если автоподгрузка недоступна.
- Показывать круговой лоудер на время загрузки изображений очередной порции; ошибка отдельного файла не блокирует следующую порцию. После исчерпания списка индикатор и кнопка скрываются.
- Превью всех пропорций — единый контейнер; `object-fit: cover; object-position: center`. Кадрирование в **карточке** визуальное и не должно менять оригинальный файл/координаты кроп-редактора. В редакторе использовать полноразмерный файл, преимущественно из `Images/prepared/` при наличии, а не обрезанное превью карточки. Оригинал с линейками остаётся на FTP для считывания размеров.
- Раздельные папки: `/Images/catalog/` хранит оригиналы с размерами, `/Images/prepared/` — очищенные версии. API подбирает подготовленное фото по совпадающему артикулу, иначе оставляет оригинал. Справочник физических размеров и ориентации — [docs/CATALOG_METADATA.md](../../CATALOG_METADATA.md) и [public/data/catalog.json](../../../public/data/catalog.json). Значения вводим по диктовке, пока они отсутствуют.
- Владелец готовит в **отдельной папке `Images/prepared`** версии без технических подписей сантиметров, линеек и управляющих маркеров; исходные изображения с линейками не заменяет. Не скрывать их через CSS — они являются частью исходного файла. Сохранять исходный артикул в имени.
- Изображения в GitHub не дублировать; каталог загружается из выделенной FTP-папки, защищённой от удаления деплоем.

**Техническая проверка:** записаны в `main` HTML/CSS/JS для пагинации, скрипт синтаксически разобран. **Проверка в браузере, включая реальную прокрутку и фотографии, пока не подтверждена.**

## Приёмка реализации (пока не проводилась)

1. Страница desktop/mobile визуально сопоставлена с референсом и использует общие токены.
2. Навигация и карточки корректны, рабочие действия честно обозначены, демо-контент маркирован.
3. Право использования опубликованных изображений проверено, чужие логотипы не заимствованы.
4. Нет ошибок консоли, переполнения на 360/390/768/1024/1440px; клавиатурная навигация доступна.
5. Проверен точный опубликованный URL, commit и критические сценарии независимым E2E после согласованного деплоя.

## Границы

Демо разрабатывается и публикуется напрямую из `main` по решению владельца. Это рабочая итерация, не финально принятая страница. Блоки AI-примерки, аккаунтов и email реализуются отдельно согласно `docs/Tasks.md`. После следующего функционального этапа провести независимый E2E.
