# 014 — AI-примерка: короткий промпт глубины и аудит фактических входов

**Дата:** 29.10.2026. **Ветка:** `fix/ai-tryon-prompt-and-payload-contract-20261029`. **Статус:** подготовлено к CI/PR, production без изменений, визуальный E2E не выполнен.

## Причина

AI-результат иногда помещает фреску **перед настоящими предметами интерьера**. Прежний канонический промпт в `public/api/_ai_tryon.php` вырос до ~13,3 КБ и многократно повторял запреты. Третья опорная фотография создаётся обычным наложением фрески на комнату без понимания глубины: на ней фреска уже может покрывать мебель. Промпт должен прямо трактовать этот preview **как схему размещения**, но не как источник истины для перекрытий.

## Проверенный контракт передачи данных (по коду, не по реальной платной генерации)

| Источник | Браузер → сервер | Сервер → подписанный manifest → GitHub runner → OpenAI |
| --- | --- | --- |
| Чистая фотография комнаты | `room` JPEG: `aiToBlob(room)` из canvas, сохраняющего композицию исходного фото (длинная сторона ограничена 1800 px) | `references[0]` → `reference-0.jpg` → `image[]` № 1 |
| Выбранный **кроп** изображения фрески | `fresco` JPEG из `crop` | `references[1]` → `reference-1.jpg` → `image[]` № 2 |
| Ручная примерка на комнате | `guide` JPEG из `core.draw(room,crop,quad,...)` | `references[2]` → `reference-2.jpg` → `image[]` № 3 |
| Размеры стены, фрески | `metadata.wall_cm`, `metadata.fresco_cm` в см | `af_ai_prompt` включает их как JSON в **тексте prompt**, не отдельными API-полями |
| Перспектива | `metadata.wall_quad`, `metadata.fresco_quad` (четыре нормализованные вершины) | Обе геометрии включаются в prompt; `fresco_quad` отдельно используется серверным `placement` для PNG-mask и композиции результата |
| Свет | `metadata.lighting`: `{tone,from,to}` либо `null` | `af_ai_prompt` включает JSON в **тексте prompt**; отдельного стандартного параметра «свет» у Images Edits нет |
| Отметки защиты объектов | `metadata.occlusion_strokes` | `placement.occlusion_strokes` → непрозрачные участки `edit-mask.png`; оригинальные пиксели восстанавливаются при compositing |
| Область редактирования | Не пользовательское фото | Runner строит серверную RGBA `edit-mask.png` и прикрепляет к OpenAI как `mask` |

Файлы трассировки: `public/assets/js/tryon.js:aiInputs`, `public/api/ai-tryon.php` (POST, signed manifest), `public/api/_ai_tryon.php:af_ai_prompt`, `.github/workflows/openai-room-tryon.yml`, `.github/scripts/protect-original-room.py`.

Исходная картинка фрески берётся из текущего выбранного кропа и при необходимости уменьшается до 1600 px; это не обязательная передача полного оригинального файла из каталога. Изображения передаются с JPEG-компрессией (quality 0.86), а не исходными байтами пользователя.\n\nOpenAI получает три изображения и PNG-маску запросом `POST /v1/images/edits` (`gpt-image-2`, `quality=medium`). Размер ответа подбирается по фактическому соотношению сторон фото комнаты. Это трассировка **на уровне исходного кода и тестового мока**: реальный сетевой запрос на production и поведение модели не измерялись.

## Изменения

1. Укорочен `af_ai_prompt` (~13,3 → ~3,5 КБ): один приоритетный принцип — реальная мебель/предметы перед фреской, затем точная геометрия, затем сохранность интерьера и физически правдоподобный свет.
2. Убраны повторные отрицания и перечисления предметов, способные провоцировать галлюцинации новых объектов.
3. Явно сказано, что третья JPEG-примерка — **не depth-correct**, а плоский guide; сохранность исходных объектов оценивается по первому изображению.
4. Сохранён структурированный JSON размеров, двух перспектив, направления/теплоты света и ограничения одного контура.
5. В PHP-тестах проверяются реальная сериализация каждого поля, наличие трёх `image[]` и маски в workflow, ограничение размера промпта; браузерный fixture проверяет 3 JPEG и передачу metadata, в т.ч. настроенного света.

## Ограничение и честная приёмка

**Промпт не создаёт достоверную карту глубины.** Серверный Pillow-compositor гарантирует сохранность исходных пикселей **вне контура** и внутри помеченных пользователем зон. При отсутствии отметок передние предметы внутри контура модель определяет вероятностно. Поэтому CI PASS подтверждает контракт передачи и регрессию пиксельной маски, но **не подтверждает фотореализм и правильную окклюзию на всех интерьерах**.

После разрешённого релиза провести небольшой независимый E2E (без избыточных платных генераций): 
- пустая комната — не добавлена мебель, один перспективный рисунок;
- комната с предметом, пересекающим край фрески — предмет полностью перед рисунком, без обрезанных силуэтов;
- комната с явно настроенным направлением света и косой перспективой — сохранены размеры, положение, свет;
- в каждом случае оригинальная комната вне фрески неизменна.

Формат E2E: версия commit, URL `https://affresco.a2ice.ru/`, шаги, артефакт, `PASS`/`FAIL`. При FAIL по предметам переднего плана следующий этап — отдельная сегментация/маска переднего плана или UX-инструмент точного выделения, а не очередное удлинение текста.

**Блокер:** Remote Desktop Commander `Dmitanium` offline, поэтому специализированный `e2e_` чат через GUI пока нельзя запустить и подтвердить.
