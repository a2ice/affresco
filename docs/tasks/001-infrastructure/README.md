# 001 — Инфраструктура AFFRESCO и GitHub Actions

Статус: in_progress. Владелец проекта подтвердил создание домена/SSL и отдельного FTP-пользователя; проверка подключения и публикация пока не проведены.

## Результат
- Публичный репозиторий `a2ice/affresco`, основная ветка `main`, исходный код и документация.
- `docs/Tasks.md`, папки задач и исключение секретов/пользовательских данных из Git.
- CI на PR в `main`; деплой из `main` через FTPS на `afreska.2ice.ru` при `FTP_TARGET_VERIFIED=true`.
- Ручной `workflow_dispatch` с `dry_run=true`; сначала безопасная проверка конфигурации, затем согласованная первая публикация.

## GitHub Secrets
`FTP_HOST`, `FTP_USER`, `FTP_PASSWORD`, `FTP_SERVER_DIR` — значения никогда не печатать в логах и не пересылать в чат.

## GitHub Variables
- `FTP_TARGET_VERIFIED=true` — устанавливать **только после подтверждения, что выделенный FTP-пользователь ограничен корнем `afreska.2ice.ru`** и путь из FileZilla интерпретирован правильно.
- Автодеплой push из `main` разрешён после проверки FTP-каталога через `FTP_TARGET_VERIFIED=true`; отдельный флаг `FTP_DEPLOY_ENABLED` больше не используется. FTP-папка `Images/` исключена из выгрузки.

В историческом WordPress-проекте «АБСУРД» FTPS работает со строгим TLS, корнем отдельного FTP-пользователя и `server-dir` относительно виртуального FTP-корня. Не копировать длинные системные пути `/var/www/...` в `FTP_SERVER_DIR`.

## План проверки
1. Через FileZilla войти **под новым пользователем** и проверить, что `/` показывает только файлы каталога AFFRESCO. Если по `/` доступны другие сайты — исправить home/chroot в ISPmanager до включения деплоя.
2. Для пользователя, изолированного непосредственно в AFFRESCO, задать `FTP_SERVER_DIR=/`. Если изоляция устроена иначе — не угадывать путь, выяснить через FileZilla и ISPmanager.
3. Запустить Actions вручную с `dry_run=true` и проверить отсутствие ошибок секретов и точный список файлов без передачи.
4. После явного согласия на первую публикацию запустить `dry_run=false`; проверить содержимое **только AFFRESCO**, HTTPS, `noindex`, файлы и отсутствие утечки секретов.
5. Независимый E2E на точном URL и коммите; только после PASS активировать `FTP_DEPLOY_ENABLED=true`.
6. Зафиксировать ссылки на run, commit и результат; только потом отметить 001 выполненной.

## Не делать
Не деплоить вне `public/`, не использовать незашифрованный FTP, не считать dry-run реальным деплоем, не включать автофлаг до приёмки.
