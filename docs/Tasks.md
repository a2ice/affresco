## Демонстрационный режим: атрибуция и защита от индексации (28.10.2026)

- **Футер:** в `public/index.html` добавлена кликабельная подпись «Создано студией a2ice.ru» с внешним HTTPS-адресом `https://a2ice.ru/`. Стили `public/assets/css/editorial.css` обеспечивают размещение рядом с copyright и адаптивность футера.
- **SEO:** главная уже имела `<meta name="robots" content="noindex,nofollow">`. Директива усилена до `noindex,nofollow,noarchive,nosnippet,noimageindex`; добавлен `public/robots.txt` со значением `User-agent: * / Disallow: /` — все поисковые обходы запрещены.
- **Принципиальное ограничение:** `robots.txt` **не гарантирует деиндексации URL**, а `Disallow: /` не даёт обычному поисковому роботу прочитать `noindex` в HTML. Эти механизмы не заменяют HTTP Basic Auth, IP allowlist или закрытый staging. Если проект нельзя показывать публично до разрешения клиента, **следующим шагом нужен пароль на весь демосайт**, согласовав доступ и проверив, что клиентская демонстрация продолжает работать.
- **HTTP-заголовок:** добавление `X-Robots-Tag: noindex` в `public/.htaccess` на данном этапе **заблокировано инструментом записи**, поэтому серверный заголовок НЕ подтверждён. При наличии доступа к хостингу настроить его отдельно на реальном веб-сервере (Apache/Nginx) и проверить ответ HTTP, в том числе для PDF/изображений/API. Важно не трогать индексирование `https://a2ice.ru/`.
- **Состояние:** код в `main`; внешним HTML GET подтверждены подпись в футере и новый meta robots. На момент первой проверки после создания `robots.txt` URL `https://affresco.a2ice.ru/robots.txt` ещё возвращал 404; проверить окончание деплоя перед статусом защиты. Независимый браузерный E2E отсутствует.

## Правила

- `[ ]` означает *не принято*; `[x]` — принято после проверки критериев из папки задачи.
- Для каждой задачи фиксировать ветку, PR/коммит, испытания, риски и результат приёмки.
- Для этого демо по решению владельца работа напрямую в `main`; деплой по push только при `FTP_TARGET_VERIFIED=true`. Перед изменениями проверять текущий состав `public/` и работоспособность маршрутов.
- В публичный GitHub не загружать пароли, API-ключи, JSON пользователей, загруженные комнаты, изображения клиентов без разрешения.
- Серверные пользовательские JSON/фотографии размещать вне веб-корня (или запрещать прямую веб-выдачу); публичным оставлять лишь разрешённые ассеты.
- Сайты `a2ice.ru` и театр «АБСУРД» не затрагивать.
