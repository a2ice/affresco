# AFreska — задачи демонстрационного прототипа

**Репозиторий:** https://github.com/a2ice/affresco  
**Планируемый демо-сайт:** https://afreska.2ice.ru/  
**Статус:** подготовка инфраструктуры; публикация и E2E пока НЕ подтверждены.  
**Технологии:** HTML/CSS/JavaScript, Alpine.js, минимальный PHP, JSON на сервере без СУБД. Не использовать Laravel и WordPress для демо.

## Реестр

- [ ] **001. Инфраструктура и автодеплой** — [задача](tasks/001-infrastructure/README.md). Отдельный репозиторий, workflow CI/FTPS, ограниченный FTP-доступ, безопасный dry-run, первая контролируемая публикация и smoke.
- [ ] **002. Лендинг по референсу** — [задача](tasks/002-landing/README.md). Адаптивная главная, премиальный визуальный язык, демонстрационный каталог.
- [ ] **003. Редактор фрески и черновики** — [задача](tasks/003-crop-drafts/README.md). Модальное окно, кроп, размеры, сохранение настроек.
- [ ] **004. Ограниченный доступ и статистика** — [задача](tasks/004-auth-quotas/README.md). Ручные аккаунты, JSON и хеши паролей, сессии, лимиты успешных/неуспешных генераций.
- [ ] **005. AI-примерка в интерьере** — [задача](tasks/005-ai-preview/README.md). Загрузка комнаты, запрос в OpenAI через PHP, очередь/статус, сохранённый результат, контроль затрат.
- [ ] **006. Отправка результата по email** — [задача](tasks/006-email/README.md). Письмо с результатом, лимиты и обработка ошибок.

## Правила

- `[ ]` означает *не принято*; `[x]` — принято после проверки критериев из папки задачи.
- Для каждой задачи фиксировать ветку, PR/коммит, испытания, риски и результат приёмки.
- Работа: отдельная ветка → PR → проверки → merge в `main` → автодеплой **только после активации флага**.
- В публичный GitHub не загружать пароли, API-ключи, JSON пользователей, загруженные комнаты, изображения клиентов без разрешения.
- Серверные пользовательские JSON/фотографии размещать вне веб-корня (или запрещать прямую веб-выдачу); публичным оставлять лишь разрешённые ассеты.
- Сайты `a2ice.ru` и театр «АБСУРД» не затрагивать.
